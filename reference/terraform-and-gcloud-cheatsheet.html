The loop

cd learners/<handle>/terraform
terraform init -backend-config="prefix=<handle>"   # once per clone; your state, your prefix
terraform fmt && terraform validate                    # what CI runs
terraform plan                                         # read it; "destroy" or another handle = stop
terraform apply -var="run=N"                             # lesson 1: N changes every time you want a batch to run
terraform apply                                        # from lesson 3: bump bronze_run / silver_run / gold_run in terraform.tfvars,
                                                       # one hop per apply, in order, waiting for each
terraform state list                                   # what Terraform believes exists

A batch is immutable: same arguments, no new run. New batch_id, new run. Keep maxExecutors = 2 and ttl on every batch: the smallest size the service allows is already far more than a drop needs, and the TTL kills a hung batch before it bills all night. Do not set a subnetwork; the bootstrap default has Private Google Access (network).

Looking at things

gcloud config list                                           # which project, which account
for l in landing bronze silver gold; do gcloud storage buckets describe gs://kuikops-lakehouse-<handle>-$l --format="value(name)"; done  # your buckets: a learner can't list the project
gcloud storage ls -r gs://kuikops-lakehouse-<handle>-landing/     # every object
gcloud storage cat gs://…/drop1/products_0.csv | head -3     # peek, never edit landing
gcloud storage cp jobs/bronze.py gs://…-landing/jobs/         # manual upload when Terraform is in the way
gcloud dataproc batches list --region=europe-west1 | grep <handle>
gcloud dataproc batches describe <id> --region=europe-west1 --format="value(state,stateMessage)"
gcloud dataproc batches wait <id> --region=europe-west1      # streams the driver log

Submitting without Terraform

gcloud dataproc batches submit pyspark jobs/bronze.py \
  --batch=<handle>-bronze-N --region=europe-west1 --version=3.0 \
  --properties=spark.dynamicAllocation.maxExecutors=2 --ttl=30m \
  --service-account=<handle>@kuikops-lakehouse.iam.gserviceaccount.com \
  --deps-bucket=gs://kuikops-lakehouse-<handle>-landing \
  -- gs://…-landing/drop1 gs://…-bronze/products

Same batch, same immutability; Terraform is just the declared form of this line (reference).

The course commands

drop next            # gate checks your pipeline, then delivers the next drop to landing
drop next --force    # delivers anyway; logged, allowed, mention it in the PR
drop check silver    # runs the ODCS contract against your silver (Friday's pass criterion)
