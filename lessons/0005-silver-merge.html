Silver: MERGE on the business key

Lesson 5 · Wednesday 13:15 · One row per barcode, the latest version wins, and a re-run changes nothing

≈ 3 hoursPrerequisite: lesson 4 (split passing)Reference: PySpark & Delta cheat sheet · glossary
Why this lesson "One row per business entity" is the line a client will hold you to. Bronze has the same barcode several times:
  • duplicates inside a drop
  • the same product again in a later drop
  • sometimes an older version after a newer one
This afternoon silver keeps one row per code, the latest last_modified, whatever the drop order and however many runs.

1. MERGE in one picture

A Delta MERGE joins a source (new rows) to a target (the table) on a condition. It handles matched and unmatched rows in one atomic commit (Delta: table deletes, updates and merges):

from delta import DeltaTable

(DeltaTable.forPath(spark, silver).alias("t")
    .merge(source.alias("s"), "t.code = s.code")       # the business key
    .whenMatchedUpdateAll()                               # same barcode: overwrite the row
    .whenNotMatchedInsertAll()                            # new barcode: insert it
    .execute())

2. Predict, then run: two traps

In a scratch script, build an empty Delta table (code, n) and a source of two rows, ("001","a") and ("001","b"). You'll run the MERGE above twice. First write down: how many rows after run one? And on run two?

What we saw — open after you ran it

First run: 2 rows, both 001. No target row matched, so both went in, with no error. Second run: [DELTA_MULTIPLE_SOURCE_ROW_MATCHING_TARGET_ROW_IN_MERGE] Cannot perform Merge as multiple source rows matched…. It only fires once the target has the key.

Second trap: a row with code = null. null = null isn't true in SQL, so it never matches and gets inserted again on every run. That's why code_missing runs in split, before the MERGE.

3. Two fixes, two lines each

Make the source unique. Keep one row per code: latest last_modified, then latest load on a tie. A window does it (row_number):

SILVER_COLUMNS = ["code", "product_name", "brands", "categories", "countries", "nutrition_grade_fr", "sugars_100g", "last_modified"]   # lesson 4's good, minus loaded_at
from pyspark.sql import Window

w = Window.partitionBy("code").orderBy(F.desc("last_modified"), F.desc("loaded_at"))
latest = good.withColumn("_n", F.row_number().over(w)).filter("_n = 1").select(*SILVER_COLUMNS)

Never let an older row win. A late update is older than silver's row, so only update when the source is newer.

.whenMatchedUpdateAll(condition="s.last_modified > t.last_modified")
Idempotent With both fixes, a re-run on the same bronze changes no rows: every match fails the > condition and nothing gets inserted. So a failed or repeated batch does no damage. On a client project an orchestrator retries a failed night run without asking you, and this is what makes that retry safe. Your pair tests this first in your PR. (Delta still commits a new version each run.)

4. Exercise: merge_silver core

Add latest(good) and merge_silver(spark, good, silver) to jobs/silver.py, and this test to tests/test_silver.py (load, late update, re-run, same rows each time):

from jobs.silver import split, merge_silver


def silver_rows(spark, path):
    return sorted((r.code, r.product_name, r.last_modified)
                  for r in spark.read.format("delta").load(path).collect())


def test_latest_last_modified_wins_and_rerun_changes_nothing(spark, tmp_path):
    path = str(tmp_path / "silver")
    good, _ = split(bronze(spark,
        ("001", "Choco",     "45", "2026-01-01"),
        ("001", "Choco bar", "44", "2026-02-01"),   # newer: wins
        ("001", "Choco bar", "44", "2026-02-01"),   # exact duplicate
        ("002", "Water",     "0",  "2026-01-01")))
    merge_silver(spark, good, path)
    late, _ = split(bronze(spark, ("002", "Old water", "0", "2025-12-01")))   # late update: older
    merge_silver(spark, late, path)
    want = [("001", "Choco bar", dt.date(2026, 2, 1)), ("002", "Water", dt.date(2026, 1, 1))]
    assert silver_rows(spark, path) == want
    merge_silver(spark, good, path)
    assert silver_rows(spark, path) == want

The first run has no table to merge into, so create it empty: if not DeltaTable.isDeltaTable(spark, silver): latest(good).limit(0).write.format("delta").save(silver) (DeltaTable API).
