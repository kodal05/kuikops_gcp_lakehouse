Your buckets and your first batch

Lesson 1 · Monday 14:15 · Declare the four layers in Terraform, run one Spark batch, receive drop 1

≈ 90 minutesPrerequisite: lesson 0 green, setup PR mergedReference: glossary · Terraform & gcloud cheat sheet
Why this lesson This week's pipeline lives in four buckets and runs as batches. Declared in code, your whole platform is a folder someone else could apply on Friday. Today's hello batch only proves the path from your laptop to a batch on GCS, so tomorrow's job is only about bronze.

1. Terraform's loop: declare, plan, apply, state

Terraform is one loop:

  1. You declare resources in .tf files.
  2. terraform plan shows the difference between those files and what exists.
  3. terraform apply makes it happen, and the state file remembers what it did.

Your state lives in the shared state bucket, under your handle as prefix. That way ten learners don't overwrite each other (Terraform docs: GCS backend). Sandbox: the instructor made this state bucket and the template's backend.tf for you. On a client project you, or their platform team, create and lock down the state bucket before the first init.

# learners/<handle>/terraform/backend.tf  (already in the template)
terraform {
  backend "gcs" {
    bucket = "kuikops-lakehouse-tfstate"
    # prefix comes from the command line so the file is identical for everyone
  }
}
cd learners/<handle>/terraform
terraform init -backend-config="prefix=<handle>"
terraform plan
Read the plan before you type yes If plan wants to destroy anything, or shows someone else's handle, your prefix is wrong. Don't apply, fix init: terraform init -reconfigure -backend-config="prefix=<handle>". The handle in terraform.tfvars doesn't set the state prefix, only init does. A 403 on someone else's bucket means the same thing.

2. Exercise: four buckets core

Declare one bucket per layer: landing, bronze, silver, gold (quarantine lives inside the silver bucket). Bucket names are global, so they include the project id and your handle. Use google_storage_bucket with just the two options below.

resource "google_storage_bucket" "landing" {
  name                        = "${var.project_id}-${var.handle}-landing"
  location                    = "europe-west1"
  uniform_bucket_level_access = true   # IAM on the bucket, no per-object ACLs
  force_destroy               = true   # sandbox: destroy may delete objects
}

Done when terraform apply reports four additions and this lists your four buckets:

for l in landing bronze silver gold; do gcloud storage buckets describe gs://kuikops-lakehouse-<handle>-$l --format="value(name)"; done

3. Exercise: a batch that proves the runtime core

A batch is one run of one job on Serverless for Apache Spark. You submit a file, and Google runs it, bills the seconds and stops (overview). The runtime already has Spark, Python and Delta, so you only ship your script (runtime versions).

Two resources, in order: put the script in a bucket (google_storage_bucket_object), then declare the batch (google_dataproc_batch). The template ships jobs/hello.py:

# jobs/hello.py: write three rows to Delta in your bronze bucket, read them back
import sys
from pyspark.sql import SparkSession

bronze = sys.argv[1]
spark = (SparkSession.builder.appName("hello")
         .config("spark.sql.extensions", "io.delta.sql.DeltaSparkSessionExtension")
         .config("spark.sql.catalog.spark_catalog", "org.apache.spark.sql.delta.catalog.DeltaCatalog")
         .getOrCreate())
df = spark.createDataFrame([(1, "landing"), (2, "bronze"), (3, "silver")], ["n", "layer"])
df.write.format("delta").mode("overwrite").save(f"{bronze}/hello")
print("rows:", spark.read.format("delta").load(f"{bronze}/hello").count())

Apply in two goes. First add only google_storage_bucket_object.hello, apply, and check the script is there: gcloud storage ls gs://…-landing/jobs/. Then add the batch under it and apply again.

resource "google_storage_bucket_object" "hello" {
  bucket = google_storage_bucket.landing.name
  name   = "jobs/hello.py"
  source = "${path.module}/../jobs/hello.py"
}

resource "google_dataproc_batch" "hello" {
  batch_id = "${var.handle}-hello-${var.run}"
  location = "europe-west1"
  runtime_config {
    version    = "3.0"
    properties = { "spark.dynamicAllocation.maxExecutors" = "2" } # drops are KBs: never scale up
  }
  environment_config {
    execution_config {
      service_account = var.service_account
      ttl             = "1800s" # a hung batch is killed after 30 min
      authentication_config {
        user_workload_authentication_type = "SERVICE_ACCOUNT" # the API sets this: declare it or every apply replaces the batch
      }
    }
  }
  pyspark_batch {
    main_python_file_uri = "gs://${google_storage_bucket_object.hello.bucket}/${google_storage_bucket_object.hello.name}"
    args                 = ["gs://${google_storage_bucket.bronze.name}"]
  }
}

Done when the batch shows SUCCEEDED and its log ends with rows: 3:

terraform apply -var="run=1"
gcloud dataproc batches list --region=europe-west1 | grep <handle>
gcloud dataproc batches describe <handle>-hello-1 --region=europe-west1 --format="value(state)"

Then change run to 2 and apply again. Terraform creates a batch, it doesn't update one: runs are immutable, hence the run number in batch_id.

4. Exercise: drop 1 core

You get each drop when you're ready, whatever the day. Drop 1 is open to all:

drop next
gcloud storage ls gs://kuikops-lakehouse-<handle>-landing/drop1/

Done when you can name the files in drop1/ and have opened one with gcloud storage cat … | head. Don't transform anything: landing's only reader is tomorrow's job.

5. The PR core

  1. Branch <handle>/terraform-buckets.
  2. Commit terraform/ and jobs/hello.py.
  3. Open the PR with the template and ask your pair.
  4. In the PR description, write one sentence in your own words on why run = 2 created a new batch instead of updating <handle>-hello-1. Your pair reads it before approving.
  5. CI runs terraform validate. Green CI plus one approval merges it.

Never commit .terraform/ or a state file. The template's .gitignore excludes them, but check it still does.

6. Stretch: find yourself in the bill stretch

Add labels = { owner = var.handle, layer = "landing" } to every bucket and apply. Find them under Billing → Reports, grouped by label. Batches bill per second in Data Compute Units, one-minute minimum (pricing). Your hello batch cost less than a coffee, now you can prove it.
