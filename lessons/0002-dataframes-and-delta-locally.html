DataFrames and Delta, locally

Lesson 2 · Tuesday 09:45 · Read a file, stamp it, append it to Delta, and watch Delta refuse a bad one

≈ 60 minutesPrerequisite: lesson 1, drop 1 in your landingReference: glossary · cheat sheet
Why this lesson This afternoon's landing→bronze batch is five moves: read, stamp, append, read back, and be refused. Practise them here, locally, on two tiny files. Bronze is the easiest hop, but a mistake there hurts most: every later layer trusts it. On a client project a source team you don't control feeds bronze, so a refused write is often your first sign they changed something.

1. One session, two configs

Delta is a table format: Parquet files plus a transaction log. Spark needs two settings for it (quick start), already in a session-scoped fixture in the template's tests/conftest.py:

from delta import configure_spark_with_delta_pip
from pyspark.sql import SparkSession

builder = (SparkSession.builder.master("local[2]")
  .config("spark.sql.extensions", "io.delta.sql.DeltaSparkSessionExtension")
  .config("spark.sql.catalog.spark_catalog", "org.apache.spark.sql.delta.catalog.DeltaCatalog"))
spark = configure_spark_with_delta_pip(builder).getOrCreate()

On the batch runtime, keep the two .config lines but skip configure_spark_with_delta_pip: Delta is already on the classpath (see lesson 1's hello.py).

2. The five moves core

Save as learners/<handle>/jobs/explore.py, run with uv run python -m jobs.explore. Before you run it, write down what the four numbered print lines will show. Then compare.

import tempfile, os
from pyspark.sql import functions as F
from tests.conftest import make_spark        # same builder as the fixture
spark = make_spark()

d = tempfile.mkdtemp(); landing = f"{d}/landing"; bronze = f"{d}/bronze"
os.makedirs(landing)
open(f"{landing}/drop1.csv", "w").write("code,product_name,sugars_100g,last_modified\n001,Choco,45,2026-01-01\n002,Water,0,2026-01-01\n")
open(f"{landing}/drop2.csv", "w").write("code,product_name,sugars_100g,last_modified\n001,Choco bar,44,2026-02-01\n,NoBarcode,1,2026-02-01\n003,Juice,10,2026-02-01\n")

# move 1: read. Every column is a string; bronze keeps it that way.
raw = spark.read.option("header", True).csv(landing)

# move 2: stamp. Which file, when.
stamped = raw.select("*",
    F.col("_metadata.file_path").alias("source_file"),
    F.current_timestamp().alias("loaded_at"))

# move 3: append.
stamped.write.format("delta").mode("append").save(bronze)

# move 4: read back.
b = spark.read.format("delta").load(bronze)
print("1. rows:", b.count())
print("2. distinct source files:", b.select("source_file").distinct().count())
print("3. sugars type:", dict(b.dtypes)["sugars_100g"])

# move 5: be refused. A drop with a new column.
try:
    stamped.withColumn("extra", F.lit(1)).write.format("delta").mode("append").save(bronze)
    print("4. appended")
except Exception as e:
    print("4. refused:", str(e).splitlines()[0][:80])

Done when you've written four predictions, run the script, and checked each one against section 3.

3. What you just saw

LineValueWhy
15Two files, five rows. Bronze appends, so the duplicate 001 is two rows, correctly.
22Each row's file. _metadata.file_path replaces input_file_name() (file metadata column).
3stringCSV gives strings and bronze doesn't cast. Typing is silver's job, and silver's risk.
4refused: A schema mismatch detected…Schema enforcement: the whole write fails, nothing partial lands (batch writes: schema validation).
The war story: why bronze refuses new columns Line 4 is why you can trust bronze. The option mergeSchema, or the session setting spark.databricks.delta.schema.autoMerge.enabled, turns the refusal into a new column with no error. The Delta docs call autoMerge "not recommended because it can lead to unintended schema changes". A real platform ran with autoMerge on: a renamed supplier column became a new null column, and nobody saw an error. Drop 4 will tempt you: a new column is a decision, not a default.
