Le gold dans BigQuery, et la suite

Leçon 10 · vendredi 13h45 · Interroge ton gold Delta depuis BigQuery sans le copier, fais-en des graphiques, et trouve où continuer à apprendre

≈ 75 minutesPrérequis : les deux tables gold écrites sur le drop 5 (leçon 9)Référence : cheat sheet PySpark & Delta (en anglais) · glossaire (en anglais)
Pourquoi cette leçon Ton gold, c'est des fichiers dans un bucket. Les analystes de ton client, eux, vivent dans BigQuery et dans des dashboards. BigQuery lit directement le log Delta, donc pas de job d'export. Toute la leçon est en stretch (le critère de validation, c'était le contrat de ce matin). C'est ce que tu montrerais ensuite en démo à un client.

1. Une table qui n'est qu'un pointeur

Une external table BigQuery sur du Delta Lake ne stocke aucune donnée. Juste le chemin du bucket et une connexion dont le service account peut le lire. Le schema vient du log Delta, du coup tu ne peux pas le modifier dans BigQuery (BigQuery: create Delta Lake tables). Le bootstrap a créé ton dataset <handle>_gold et la connexion. Toi, tu écris juste le DDL. Sandbox : sur un projet client, la connexion et le droit de lecture de son service account sur le bucket gold passent en général par une demande IAM à quelqu'un d'autre. Demande-la dès la première semaine.

CREATE EXTERNAL TABLE `kuikops-lakehouse.<handle>_gold.nutriscore_by_category`
  WITH CONNECTION `kuikops-lakehouse.europe-west1.gold-reader`
  OPTIONS (
    format = "DELTA_LAKE",
    uris   = ["gs://kuikops-lakehouse-<handle>-gold/nutriscore_by_category"]
  );

Les limites à connaître avant qu'un client pose la question (même page). Tes tables gold n'en touchent aucune :

  • pas de change data capture
  • pas de vues matérialisées
  • pas de BigQuery Storage Read API
  • pas de colonnes timestamp_ntz

2. Exercice : les deux tables gold dans BigQuery stretch

Dans la console BigQuery (ou avec bq query --use_legacy_sql=false), crée les deux external tables. Ensuite, en SQL : quelle catégorie a la plus grosse part de produits en grade e en France ?

C'est bon quand les deux tables apparaissent dans ton dataset et que ta requête renvoie une seule catégorie.

3. Exercice : est-ce que BigQuery voit un nouveau gold ? stretch

La doc ne dit pas clairement si une requête voit les commits Delta faits après la création de la table. Du coup, mesure-le :

  1. Note un chiffre de brands_sugar.
  2. Change un truc en amont qui le fait bouger, puis relance le silver et le gold.
  3. Refais la requête sans toucher à l'external table.

Poste ton résultat dans le canal Teams avec les ids de batch. Si vous êtes deux à ne pas être d'accord, lancez un thread.

4. Exercice : un graphique par question stretch

Dans Looker Studio, ajoute une source de données BigQuery sur chaque table et fais un graphique pour chacune :

  • des barres empilées de part de grade par catégorie, avec un filtre pays
  • un graphique en barres des top marques par nombre de produits, coloré selon le sucre moyen

Si un graphique a besoin d'un filtre ou d'une colonne que la table gold n'a pas, stop. C'est une nouvelle table gold dans gold.py, pas un champ calculé dans le dashboard.
