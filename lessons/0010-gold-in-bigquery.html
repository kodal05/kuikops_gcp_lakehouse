Gold in BigQuery, and what comes next

Lesson 10 · Friday 13:45 · Query your Delta gold from BigQuery without copying it, chart it, and find where to keep learning

≈ 75 minutesPrerequisite: both gold tables written on drop 5 (lesson 9)Reference: PySpark & Delta cheat sheet · glossary
Why this lesson Your gold is files in a bucket, and your client's analysts live in BigQuery and dashboards. BigQuery reads the Delta log directly, so no export job. The whole lesson is stretch (the pass criterion was this morning's contract). It's what you'd demo to a client next.

1. A table that's just a pointer

A BigQuery external table over Delta Lake stores no data, just the bucket path and a connection whose service account can read it. The schema comes from the Delta log, so you can't edit it in BigQuery (BigQuery: create Delta Lake tables). The bootstrap created your dataset <handle>_gold and the connection. You only write the DDL. Sandbox: on a client project, the connection and its service account's read on the gold bucket are usually an IAM request to someone else. Ask for it in week one.

CREATE EXTERNAL TABLE `kuikops-lakehouse.<handle>_gold.nutriscore_by_category`
  WITH CONNECTION `kuikops-lakehouse.europe-west1.gold-reader`
  OPTIONS (
    format = "DELTA_LAKE",
    uris   = ["gs://kuikops-lakehouse-<handle>-gold/nutriscore_by_category"]
  );

Limits to know before a client asks (same page), none of which your gold tables hit:

  • no change data capture
  • no materialized views
  • no BigQuery Storage Read API
  • no timestamp_ntz columns

2. Exercise: both gold tables in BigQuery stretch

In the BigQuery console (or bq query --use_legacy_sql=false), create both external tables. Then in SQL: which category has the highest share of grade e products in France?

Done when both tables appear in your dataset and your query returns one category.

3. Exercise: does BigQuery see a new gold? stretch

The docs don't say clearly if a query sees Delta commits made after the table's creation. So measure it:

  1. Note one number from brands_sugar.
  2. Change something upstream that moves it, then re-run silver and gold.
  3. Query again without touching the external table.

Post your result in the Teams channel with the batch ids. If two of you disagree, start a thread.

4. Exercise: one chart per question stretch

In Looker Studio, add a BigQuery data source on each table and build one chart for each:

  • stacked bars of grade share per category, with a country filter
  • a bar chart of top brands by product count, coloured by average sugar

If a chart needs a filter or column the gold table doesn't have, stop. That's a new gold table in gold.py, not a calculated field in the dashboard.
